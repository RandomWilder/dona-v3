# Slice 3.2 — evidence that a red check blocks the merge

Slice 3.2's acceptance bar is not "CI exists", it is "red blocks merge". A gate
that has never been observed failing is an assumption, so it was failed on
purpose once.

## Setup

`main` protection now requires two status checks (added this slice, closing the
open item from slice 1.2):

```
required_status_checks: { strict: true, contexts: ["gate", "evals"] }
allow_force_pushes: false · allow_deletions: false · enforce_admins: false
```

## The green run — PR #1 (the slice itself)

https://github.com/RandomWilder/dona-v3/pull/1

```
evals   pass   13s
gate    pass   29s
```

From the `gate` job log — the number that matters, because `pg-support.ts`
skips the durability suite when Postgres is unreachable:

```
ℹ tests 40
ℹ pass 40
ℹ fail 0
ℹ skipped 0
```

**0 skipped** — the Postgres service is real and slice 3.1's durability tests
(restart, two-runner race, backoff) actually executed in CI. Without
`REQUIRE_POSTGRES=1` a missing service would have printed `skipped 18` and a
green tick.

## The red run — PR #2 (deliberately broken)

https://github.com/RandomWilder/dona-v3/pull/2

One line changed: `httpStatus('conflict')` 409 → 200, caught by
`src/kernel/errors.test.ts`.

```
gate    fail   29s
evals   pass   14s
```

The `gate` job log:

```
✖ maps every code to its status
    actual: 200,
    expected: 409,
ℹ tests 40
ℹ fail 1
```

And the merge state GitHub reports for that PR:

```json
{ "mergeStateStatus": "BLOCKED", "mergeable": "MERGEABLE", "state": "OPEN" }
```

`MERGEABLE` means there is no conflict — nothing about the diff prevents the
merge. `BLOCKED` is the required `gate` check refusing it. That distinction is
the whole proof: the branch was mergeable and the gate stopped it anyway.

Note `evals` passed on the broken PR. That is correct and intentional — the
break is in the kernel, not the golden set. The two jobs are separate so a
quality regression never hides behind a build failure, or vice versa.

## Disposition

PR #2 closed unmerged; branch `ci/prove-broken-gate` kept. The commit stays in
repo history as slice 3.2's Verify artifact — per `tasks/todo.md`, "the
deliberately-broken PR in repo history".
