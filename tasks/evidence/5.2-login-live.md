## The cookie flag no local test can prove

```
set-cookie: dona_session=; Path=/; HttpOnly; SameSite=Lax; Max-Age=0; Secure
```

Cloud Run terminates TLS at Google's front end, so the process itself only ever
sees plain http — `request.protocol` alone would never mark the cookie `Secure`
in production. Its presence here proves `isHttps()` reads `x-forwarded-proto`
correctly behind the proxy. Obtained without the password by using `/admin/logout`,
which clears the cookie whether or not a session existed.

## The rollback rehearsal, on the real release

Slice 4.2 proved the round trip when both revisions served the same JSON body. This
one is visible: `00003-8jc` (shells + login) against `00002-dwz` (bare `/health`).

| # | action | result | time |
|---|---|---|---|
| 1 | `./infra/rollback.sh prod` | `00003-8jc` → `00002-dwz`, smoke green on the target | **11s** |
| 2 | check | `/`, `/admin`, `/admin/login`, `/t/demo` all 404; `/health` still `ok:true, db:up` | — |
| 3 | `update-traffic --to-latest` | back to `00003-8jc`, un-pinned (`latestRevision: True`) | **8s** |
| 4 | check | full surface restored, smoke green | — |

Two things this made concrete that the 4.2 rehearsal could not:

1. **A rollback rolls back code, not schema.** Migration `0003_staff_auth.sql` stayed
   applied throughout; `00002-dwz` simply does not know those tables exist. Had the
   migration been destructive, rolling the code back would not have saved anything —
   which is exactly why `.cursor/rules/migrations.mdc` forbids dropping a column in the
   same release that stops writing it.
2. **The 404 body changed shape.** Rolled back, prod answered
   `{"message":"Route GET:/admin not found","error":"Not Found","statusCode":404}` —
   Fastify's own body, echoing the requested path and naming the framework. Rolled
   forward: `{"code":"not_found","message":"route not found"}`. The before-and-after of
   the edge error handler added in 5.1.

## What the login is, and is not

One seeded operator, a 12-hour absolute session, a 5-in-15-minutes failed-attempt
throttle. **No roles** — admin/operator/viewer and "a viewer cannot mutate, proven by
test" are ROADMAP week 2, and nothing behind `/admin` reads data yet.

Not in place, named in `SPEC-staff.md` rather than implied: CSP headers, per-IP rate
limits, password rotation and change flow, login CSRF. All week 6.

**The one operational trap**, documented in `docs/runbook-deploy.md`: seeding creates an
operator and never updates one. A new password secret version has no effect once the
account exists.
