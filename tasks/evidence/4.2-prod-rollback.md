# Evidence — Slice 4.2: prod deploys on a tag, and rolls back in one command

Captured 2026-08-23. GitHub Actions runs age out of the UI; this is the
durable record.

## The acceptance bar

"You have deployed AND rolled back prod today, both on purpose. **Verify:**
Cloud Run revision history shows the round-trip."

Prod round-trip, all four moves deliberate:

| # | action | how | result |
|---|---|---|---|
| 1 | release | tag `v0.0.1-rc.1` | `dona-prod-00001-c8s` created, 100% traffic |
| 2 | release | tag `v0.0.1-rc.2` | `dona-prod-00002-dwz` created, 100% traffic |
| 3 | **rollback** | `./infra/rollback.sh prod` | back to `00001-c8s`, **10 seconds**, smoke green |
| 4 | roll forward | `update-traffic --to-latest` | `00002-dwz` again |

```
$ ./infra/rollback.sh prod
▸ dona-prod: dona-prod-00002-dwz → dona-prod-00001-c8s
Routing traffic..............................................................done
Traffic:
  100% dona-prod-00001-c8s
smoke ok — https://dona-prod-ydabrrmura-zf.a.run.app/health → {"ok":true,"version":"0.1.0-dev","db":"up"}
```

No rebuild, no CI wait, no console. Ten seconds is the number that matters:
it is short enough that rolling back is the *first* thing you reach for in an
incident rather than the last.

## The releases

| tag | run | jobs | wall clock |
|---|---|---|---|
| `v0.0.1-rc.1` | [32627131362](https://github.com/RandomWilder/dona-v3/actions/runs/32627131362) | `gate / gate` ✓ · `gate / evals` ✓ · `prod` ✓ | 1m57s |
| `v0.0.1-rc.2` | [32627283545](https://github.com/RandomWilder/dona-v3/actions/runs/32627283545) | `gate / gate` ✓ · `gate / evals` ✓ · `prod` ✓ | 1m46s |

The `gate / *` jobs are the point. Tags do not match `ci.yml`'s push filter,
so a tag push would otherwise deploy to production having proven nothing.
`ci.yml` gained a `workflow_call` trigger and `release.yml` calls it, so the
tagged commit clears typecheck, lint, the durability suite against Postgres,
and the golden set **before** an image is built. Never release red.

The release also refuses to continue unless the tag is an ancestor of
`origin/main` — a tag can be cut from any branch; production ships main.

## The prod environment

- **Its own Cloud SQL instance** `dona-v3:me-west1:dona-prod` — POSTGRES_16,
  ENTERPRISE, db-f1-micro, zonal, **backups 02:00 UTC, 7 retained** (staging
  has none). Rationale in `docs/decisions/ADR-0001-prod-database-isolation.md`;
  ROADMAP's architecture table amended to match.
- **Secret isolation verified, not assumed:**
  ```
  prod-database-url    → ['serviceAccount:app-prod@dona-v3.iam.gserviceaccount.com']
  staging-database-url → ['serviceAccount:app-staging@dona-v3.iam.gserviceaccount.com']
  ```
  Exactly one runtime identity per secret. A leaked staging URL cannot reach
  prod, and the two instances share no endpoint.
- Separate deploy identity `deploy-prod`, Workload Identity Federation, no
  long-lived keys. Provider still pins `assertion.repository`.
- Rebuildable: `./infra/bootstrap.sh prod`.

## The smoke gate fails loudly

`infra/smoke.sh` is one definition of "up", used by both deploy workflows and
by hand. It requires `"db":"up"` as well as `"ok":true` — a process that boots
but cannot reach Postgres is "deployed but silently broken" (PIPELINE.md §5).
Proven to fail, not just to pass:

```
$ SMOKE_ATTEMPTS=2 ./infra/smoke.sh https://dona-prod-ydabrrmura-zf.a.run.app/nope
  attempt 1/2: <no response>
  attempt 2/2: <no response>
SMOKE FAILED — .../nope/health never returned ok:true with db:up
exit=1
```

## Findings worth carrying

1. **A rollback pins traffic, and it stays pinned.** `update-traffic
   --to-revisions X=100` takes a service off "follow latest". The next
   `gcloud run deploy` then creates a revision serving **0%** — a green
   pipeline that changes nothing in production. Both workflows now end with
   `--to-latest`.

   This was caught by rehearsing `rollback.sh` against *staging* before
   touching prod, which is the only reason `deploy.yml` was fixed too rather
   than shipping the same trap on the staging side. It was then proven the
   honest way: staging was left deliberately pinned to `00002-qp8`, and
   merging [PR #3](https://github.com/RandomWilder/dona-v3/pull/3) un-pinned
   it — `00004-dzz`, `latestRevision: true`. The fix was demonstrated, not
   asserted.

2. **Refactoring proven infrastructure needs its own proof.**
   `staging-bootstrap.sh` became `bootstrap.sh <staging|prod>` so two
   environments cannot drift. Before it was pointed at prod it was re-run
   against **live staging**: clean no-op, nothing created, password untouched,
   staging `/health` still green.

3. **Tags are invisible to a branch-filtered CI workflow.** Easy to ship a
   release pipeline that looks gated and isn't. `workflow_call` is the fix,
   and the `gate / *` jobs in the run list are the visible evidence it ran.
