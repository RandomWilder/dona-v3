## Migrations applied on deploy

`boot.ts` awaits `migrate(pool)` **before** `app.listen()`, so the process cannot serve traffic unless every migration succeeded. Cloud Run logs for revision 00001:

```
Default STARTUP TCP probe succeeded after 1 attempt for container "app-1" on port 8080.
dona-v3 0.1.0-dev listening on 0.0.0.0:8080
```

No `severity>=ERROR` entries. That line printing is proof migration `0001_init.sql` ran on Cloud SQL — which settles the one assumption flagged in the plan: **Cloud SQL for PostgreSQL 16 accepts `CREATE EXTENSION vector`.**

## What this environment is

- **Region me-west1 (Tel Aviv)** — tenant PII stays in Israel.
- **Cloud SQL** `dona-v3:me-west1:dona-staging`, POSTGRES_16, db-f1-micro, reached over the Cloud SQL unix socket; the connection URL lives in Secret Manager and is mounted as `DATABASE_URL`.
- **No long-lived keys.** CI authenticates by Workload Identity Federation. The provider pins `assertion.repository == 'RandomWilder/dona-v3'`; without that condition any GitHub repository could mint tokens for this project.
- **Separate identities**: `deploy-staging` (push images, roll revisions) and `app-staging` (reach the database, read its own secret).
- Rebuildable from `infra/staging-bootstrap.sh` — idempotent, no console clicks.

## Findings worth carrying

1. **me-west1 defaults new Cloud SQL instances to `ENTERPRISE_PLUS`**, which rejects shared-core tiers. `--edition=ENTERPRISE` is required for `db-f1-micro`. First bootstrap run failed on exactly this.
2. **Deploy triggers on CI succeeding, not on push.** A red commit therefore cannot reach staging even though branch protection has `enforce_admins: false`. The workflow checks out `github.event.workflow_run.head_sha`, since `workflow_run` otherwise hands you the default-branch tip rather than the commit that passed.
3. **Local Docker on this machine cannot resolve Docker Hub metadata** (`DeadlineExceeded`) although curl reaches the registry in under a second — a Docker Desktop issue, not the network. Base image is `node:24-slim`, which was already cached locally and is the safer glibc choice. Expect this to bite any local `docker build`.
